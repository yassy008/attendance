# Firebase の準備（先生にお願いする作業）

学生のスマホから出席できるようにするため、データの保管場所として Firebase を用意します。
**すべて無料プラン（Spark）の範囲で、クレジットカードの登録は不要です。**

所要時間は15分ほどです。画面の文言は時期によって少し変わることがあります。

---

## 手順1：Firebase プロジェクトを作る

1. https://console.firebase.google.com を開き、Googleアカウントでログインします。
2. 「プロジェクトを追加」を押します。
3. プロジェクト名を入力します（例：`attendance-meijo`）。
4. Google アナリティクスは **「無効」** にします（出席管理には不要です）。
5. 「プロジェクトを作成」を押し、完了するまで待ちます。

## 手順2：データベース（Firestore）を作る

1. 左のメニューの「Database と Storage」→「Firestore Database」を開きます（左上の「商品を検索」からも開けます）。
2. 「データベースの作成」を押します。
3. **ロケーションは `asia-northeast1 (Tokyo)` を選びます。**
   これは**後から変更できません**。必ず東京を選んでください。
4. 「本番環境モードで開始」を選びます（アクセス制限のルールは、あとで私が用意します）。
5. 「作成」を押します。

## 手順3：ログインの方法を有効にする

1. 左のメニューの「セキュリティ」→「Authentication」を開きます（左上の「商品を検索」に `Authentication` と入力しても開けます）。
2. 「始める」を押します。
3. 「Sign-in method」（ログイン方法）のタブを開きます。
4. **Google** を選び、「有効にする」をオンにします。
   - 「プロジェクトの公開名」は、Googleログインの画面に表示される名前です（例：`出席確認`）。
   - 「プロジェクトのサポートメール」は、先生のメールアドレスを選んでください。
   - 「保存」を押します。これが**先生用のログイン**になります。
5. 「ログイン方法」タブに戻り、右上の **「新しいプロバイダを追加」** から **匿名**（Anonymous）を選んで、「有効にする」をオンにし保存します。
   - これは**学生の端末を見分けるため**のものです。学生がログインしたり、名前を入力したりする必要はありません。「1台の端末から1人だけ」の制限に使います。

## 手順4：ウェブアプリとして登録し、設定値をコピーする

1. 画面左上の歯車マーク →「プロジェクトの設定」を開きます。
2. 下のほうの「マイアプリ」で、**ウェブ（`</>` のマーク）** を選びます。
3. アプリのニックネームを入力します（例：`attendance-web`）。
4. **「Firebase Hosting も設定する」にはチェックを入れません**（公開は GitHub Pages で行うためです）。
5. 「アプリを登録」を押すと、次のような設定値が表示されます。

```js
const firebaseConfig = {
  apiKey: "AIza....",
  authDomain: "attendance-meijo.firebaseapp.com",
  projectId: "attendance-meijo",
  storageBucket: "attendance-meijo.appspot.com",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abcdef123456"
};
```

**この内容をそのままコピーして、チャットに貼り付けてください。**
これは公開してよい値です（秘密の鍵ではありません）。データを守るのは、次の手順のアクセス制限ルールです。

## 手順5：あとで必要になる設定（公開のときに行います）

GitHub Pages で公開したあとに、Authentication →「設定」→「承認済みドメイン」に、
公開先のドメイン（例：`<ユーザー名>.github.io`）を追加します。
動作確認に使う `localhost` は、最初から登録されています。

## 私（Claude）が行う作業

1. **アクセス制限のルール**を作り、Firebase に設定していただきます。
   - 名簿と出席記録は、**作成した先生だけ**が読み書きできる。
   - 学生の画面には、**氏名と座席だけ**を渡し、学籍番号は渡さない。
   - 学籍番号の照合は Firebase 側で行う（学生のブラウザからは名簿を読めない）。
   - 1回の授業につき、1つの端末から登録できるのは1人まで。
2. 先生用の **Googleログイン画面**を追加します。
3. データの保存先を、いまの「このPCのブラウザ内」から Firebase に切り替えます。

## 費用の目安

無料プランの上限は、1日あたり読み取り5万回・書き込み2万回です。
100人の授業を1日に数コマ行っても収まる見込みです（学生の画面は、出席登録が終わると通信を止める作りにします）。

# 手順6：アクセス制限のルールを設定する（最後の作業）

設定値をいただいて、接続の実装が終わりました。最後に、データを守るルールを登録します。

1. Firebase の画面で「Firestore Database」を開き、上のタブの **「ルール」** を選びます。
2. 表示されている内容を**すべて消して**、この作業フォルダにある **`firestore.rules`** の中身をそのまま貼り付けます。
3. **「公開」** ボタンを押します。

これで次のようになります。

| 誰が | できること |
|---|---|
| 担当の先生（Googleログイン） | 自分が作った授業の名簿・出席記録の読み書き |
| 学生（ログインなし） | 授業名と座席の配置、席に座っている人の**氏名**の閲覧 |
| 学生（出席登録） | **学籍番号が名簿と一致する場合だけ**登録できる。1回の授業につき1つの端末から1人だけ |
| ほかの先生・第三者 | 名簿（学籍番号）と出席記録は読めない |

## 使い方（ルールの公開後）

1. `index.html` を開き、「Googleでログイン」を押します。
2. 授業を作り、名簿を読み込みます。
3. 学生用URL（QRコード）を学生に配ります。学生はログインせずに出席登録できます。

## 公開（GitHub Pages）のときに必要な作業

Authentication →「設定」→「承認済みドメイン」に、公開先のドメイン（例：`<ユーザー名>.github.io`）を追加します。
これを忘れると、公開したページで先生のログインができません（学生の出席登録には影響しません）。

# 追加の設定：大学のアカウントだけが使えるようにする

公開後に見知らぬ人が使ってしまわないよう、教員としてログインできるアカウントを
**@meijo-u.ac.jp のみ**に制限しています（2か所で設定しています）。

- `firestore.rules` の `isTeacherAccount()`：Firebase 側で、他のアカウントからの授業作成を拒否します。
- `js/firebase-config.js` の `allowedEmailDomain`：画面側で「このアカウントでは使えません」と案内します。

他大学の先生にも使っていただく場合は、この2か所を変更します（空にすると、どのGoogleアカウントでも使えます）。
学生の出席登録には、この制限は関係ありません（ログイン不要のままです）。
